# Code Review — Day 21 (Month 2 Week 4 Day 3: Titanic rebuild + comparison table + misclassified indices)

Scope: readability, structure, naming, idiomatic Python only. Correctness not re-litigated (tests 5/5 passing).

## Findings

1. Cross-day bare import via a `sys.path` shim — `evaluate.py:8-11` does `sys.path.insert(0, ... / "day_2" / "code")` followed by `from eda import load_csv, is_missing` and `from encode import to_float_column, fill_mean, label_encode`. This is the Day-9/Day-14/Day-17/Day-20 shape again (Day 19's all-relative fix not followed here), and it makes the module importable only with the shim. Prefer a documented path note or a real package import so `evaluate.py` imports from any cwd.
2. Two unused imports plus import-order drift — `is_missing` (`:10`) is never referenced in the file, and `csv` (`:13`) is never referenced either (only the parameter name `csv_path` contains "csv"). Delete both. While there, `import csv` sits *after* the local `from eda`/`from encode` imports (`:10-11` vs `:13`); stdlib imports belong grouped at the top (`pathlib`, `sys`, then local), not interleaved.
3. `range(len(...))` indexing in the `X` assembly — `:53-63` does `X = []` then `for i in range(len(valid_rows)): X.append([pclass[i], float(sex[i]), ...])`. Zip the already-parallel columns instead: `for pc, s, a, ss, pa, f, e in zip(pclass, sex, age, sibsp, parch, fare, embarked)` (or build `X` as one comprehension). The filter loop just above (`:33-36`, `for row in rows`) already uses direct iteration — copy that shape here.
4. Manual filter-then-append where a comprehension reads better — `:33-36` builds `valid_rows` with `valid_rows = []` + `for` + `if` + `append`. This is a well-named accumulator (not a vague-`output` case), but the single-condition filter is the comprehension shape: `valid_rows = [row for row in rows if len(row) > embarked_idx and row[embarked_idx].strip() != ""]`.
5. Abbreviated unpack names against an opaque row type — `comparison_table(:83)` unpacks `for name, acc, prec, rec, f1 in results` while the header spells out `Accuracy/Precision/Recall/F1`, and `misclassified_indices(:103)` uses single letters `for idx, (t, p) in enumerate(zip(...))`. Prefer `acc → accuracy` (or at least `acc → acc_` consistently), `prec/rec → precision/recall`, and `t, p → true_label, pred_label`. Related structure note: `results: list[tuple[str, float, float, float, float]]` (`:68`) is four positional floats that are easy to transpose at a call site; a small `NamedTuple` (`name/accuracy/precision/recall/f1`) would make call sites self-documenting without changing the printed output.
6. Micro-slips: magic widths and stray whitespace — the `15`/`10` widths are repeated six times across `:79` and `:84` with no named constant (e.g. `_NAME_W = 15; _NUM_W = 10`), so a future width change must land in two places at once; and `:30` is a blank line carrying trailing spaces. Also minor: `csv_path: str` (`:16`) could accept `str | os.PathLike` so `pathlib.Path` callers do not need `str(...)` first.

- Guard order is the fixed shape: `misclassified_indices(:97-100)` checks emptiness *before* length-mismatch, avoiding the Day-10 `binary_log_loss` inversion; `load_titanic_xy(:26,38)` similarly guards `rows/header` then `valid_rows` as two distinct stages rather than one collapsed check.
